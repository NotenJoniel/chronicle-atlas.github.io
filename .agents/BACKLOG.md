## ✅ 最重要方針：論理的統合 + 物理的分割 【実施済み 2026-08-04】

**「1つのデータベースにまとめる」≠「1つのファイルにまとめる」**

現在のサブプロジェクト方式（各ディレクトリに `app.js` + `styles.css` + `index.html`）は維持。
データは `data/timelines/*.json` に統一スキーマで格納。各 `app.js` は `fetch` で読み込む。

### 現在のディレクトリ構造

```
data/
  schema.json          ← 共通の型定義（JSON Schema）
  index.json           ← 各タイムラインのメタ情報
  timelines/
    warring-states.json
    chu-han.json
    three-kingdoms.json
    sengoku-japan.json
    roman-empire.json
```

### 統一済みフィールド名（camelCase）
`eraPhases`, `factions`, `categories`, `characters`, `events`, `mapSnapshots`, `wikiLinks`
- 旧 `TERRITORY_SNAPSHOTS` / `MAP_SNAPSHOTS` → `mapSnapshots` に統一済み

### なぜこの構造か

- **AIのコストはファイル単位**: 三国時代の編集時に読むのは `schema.json` + `three-kingdoms.json` だけ。他のタイムラインは一切コンテキストに入らない。
- **機能の恩恵はスキーマ単位**: 全ファイルが同じフィールド名で書かれているので、横串ビューはビルド時にマージするだけで成立。
- **コスト感の実数**: 出来事1件 ≒ 250〜400トークン。150件で4〜6万トークン。1ファイル200〜300件を超えたら期間で分割（例: `han-western.json` / `han-eastern.json`）。

### 🚨 引き続きの警戒対象：スキーマドリフト

新規タイムライン追加時は必ず `data/schema.json` と既存JSONファイルのフィールド名を参照すること。

**→ スキーマを共有することが、将来の大規模リファクタを回避する投資。**

## 🔴 今決めておくべきこと（安いうちに）

### 1. フィールド名と型の統一
- 年の持ち方（`year` フィールド、紀元前は負数 `-221` など）
- 紀元前の表現方法
- 確度フラグ（`certainty: "confirmed" | "disputed" | "approximate"`）
- 分類タグの語彙（全時代共通のカテゴリ定義）

### 2. IDの命名規則
- ファイルを開かずに参照できる形: `three-kingdoms/battle-of-red-cliffs`
- タイムライン横断でユニークなID体系

### 3. バリデーションスクリプト
- CIで型チェック → AIが生成したデータを人間が読んで検証する必要がなくなる
- これもコンテキスト節約になる

### 4. 整形済みJSON
- minify禁止（diffが壊れて部分編集ができなくなる）
- Pretty-printで保存

> **NOTE**: 固有名詞の統一辞書のようなものは後からでも十分間に合うので今は不要。

## 🟡 設計課題（優先度：中）

### 5. 分類タグの全時代共通化
- **現状**: 各サブプロジェクトで独自のカテゴリ定義（戦国は「戦・政・人・城」、三国志は別定義など）
- **方針**: 全時代共通の分類軸を定義し、「政変だけ追う」「合戦だけ追う」といったフィルタを全時代で統一的に機能させる
- **効果**: 単なる年表から「歴史データベース」に進化

### 6. 年代の扱い方針
- **課題**:
  - 紀元前の年数え
  - ユリウス暦とグレゴリオ暦のずれ
  - 和暦・元号との対応
  - 諸説ある年代の表示（例：北条早雲の伊豆討ち入り 1493年説 vs 1491年説）
- **方針**: データ側に「確度」フィールドを持たせ、UIで点線や補足表示で区別
- **効果**: 歴史好きからの信頼度が大幅向上

### 7. 群雄割拠期の人物を独立勢力として表現する
- **現状**: `three-kingdoms.json` の勢力図（`mapSnapshots`）では董卓・袁紹・劉表・劉璋などが個別の色分けされた勢力として表示されているが、`characters[]` 側は全員 `faction: "other"`（群雄）に一括りにされており、サイドバーでは区別されない
- **背景**: 三国鼎立前の群雄割拠期（董卓・呂布・袁紹・袁術・劉表・公孫瓚が割拠し、劉備はまだ弱小だった時代）が物語として最も動きが激しく面白い部分だが、現状の人物側データではその迫力が表現できていない
- **方針**: 董卓・呂布・袁紹・袁術・劉表・公孫瓚をそれぞれ独立した `factions{}` エントリに昇格させ、人物データの `faction` 値も更新。サイドバーの勢力別セクション・勢力フィルタ・タグ色分けが自動的に個別表示されるようにする
- **注意**: これは2026-08-05のG1/G2改修（`.agents/DESIGN.md` G1/G2）でスコープ外とした。地図専用の疑似勢力（`mapOnly:true`）としては既に `dongzhuo`/`ensho`/`liubiao`/`liuzhang` が `factions{}` に登録済みなので、そこから `mapOnly` を外して人物にも紐付ける形が実装の起点になる

### 8. G2残項目：時代固有設定のデータ層移行（続き）
- **現状**: 2026-08-05のG1/G2改修で `factionOrder`・凡例ラベル・初期表示年はデータ駆動化済み（`.agents/DESIGN.md` G2参照）。地図専用の疑似勢力（董卓・袁紹・劉表・劉璋・係争地）も `mapOnly:true` で `factions{}` に正式登録済み
- **残っている項目**:
  - **勢力の色**: 各 `styles.css` の `--roma` 等のCSS変数・`.map-roma` 等のクラス定義がハードコードのまま。`factions[].color` へのデータ化が未対応
  - **three-kingdomsの地図レイアウト**: `three-kingdoms/app.js` の中国地図固定レイアウト配列（`MAP_LAYOUT`、5×4グリッド）が他6本の「件数から動的に列数計算」方式と異なる構造のまま
  - **旧世代3本の静的フィルタボタン**: `warring-states`/`chu-han`/`three-kingdoms` の `index.html` は勢力・カテゴリフィルタボタンが静的ハードコード。新世代4本（`han-dynasty`/`sengoku-japan`/`roman-republic`/`roman-empire`）は `renderFactionFilters()`/`renderCategoryFilters()` で動的生成済みだが未統一
- **方針**: G3（描画層の重複解消・`shared/timeline-core.js` への統合）着手時にまとめて対応する。7本の `app.js` が95%同一コードである状態を解消するタイミングで、色・地図レイアウト・フィルタボタン生成方式も同時に揃えるのが差分最小
- **補足**: `validate.js` に `mapSnapshots[].territories[].faction` が `factions{}` に存在するかを検証するチェックを追加すると、今回発見したような疑似勢力の登録漏れを機械的に防げる（今回は実害を手動確認して `mapOnly` 登録で解消したが、再発防止策としては未実装）

### 9. JavaScript描画によるSEO問題
- **現状**: タイムラインの中身はJS描画のため、HTMLソースに含まれない
- **影響**: 検索エンジンのクローラ、SNSカード生成、外部ツールからの参照で年表データが「無いもの」として扱われる
- **対策案**:
  - ビルド時に静的HTMLを生成（SSG化）
  - 最低限: 各タイムラインページに主要テキストをサーバー側で埋め込む
- **追加施策**: 個々の出来事にアンカーリンク（例: `/three-kingdoms#red-cliffs`）を振る → 共有性と検索流入が大幅改善

## 🟢 コンテンツ拡充ロードマップ（優先度順）

### 最優先：漢帝国（前漢・後漢）
- 既存3本の中国系タイムライン（戦国→楚漢→三国）をつなげる最重要ピース
- 楚漢戦争終結（BC202）〜 三国時代開始（AD184）の**約400年が空白**
- 武帝の対匈奴戦争、張騫の西域派遣、王莽の新、光武帝、党錮の禁→黄巾の乱

### 次点：ローマ共和政
- ローマ帝国編の前史を埋める
- ポエニ戦争、グラックス兄弟、カエサルまで
- 中国の戦国時代と時期が重なり「同じ頃、地中海と黄河流域で何が起きていたか」の比較が成立

### その後の展開候補
| 候補 | 理由 |
|---|---|
| **モンゴル帝国** | ユーラシアを東西に貫き、中国系とヨーロッパ系タイムラインの「結節点」として機能 |
| **ヘレニズム時代**（アレクサンドロス） | 中国戦国時代と同時代、全く別の論理で動く対比が劇的 |
| **大航海時代・宗教改革** | 日本の戦国時代とセットにすることで「鉄砲伝来やザビエル来日の世界史的文脈」が線でつながる |

### 日本の戦国時代（実装済み）への補足
- 既存コンテンツと800年以上離れるため「単発の島」になっている
- 同時代のヨーロッパ（大航海時代、宗教改革、ハプスブルク家）をセットで追加すると差別化が強化される

## 🔵 目玉機能候補

### 横串ビュー（同時代比較）
- **概要**: 複数文明を同一の時間軸に重ねて表示する機能
- **意義**: 個別の年表は他サイトにもあるが、複数文明の同時代比較ができるサイトは希少
- **効果**: サイト名「Atlas」のコンセプトが最も活きる機能
- **前提**: データとUIの分離（スキーマ共通化）が完了していること

### 共通アーキテクチャ（現行）
- 各サブプロジェクトは `app.js` + `styles.css` + `index.html` の3ファイル構成
- データは `data/timelines/<name>.json` に統一スキーマ（camelCase）で格納
- `app.js` が `fetch('../data/timelines/<name>.json')` でデータを読み込み、旧キー名にマッピングして使用
- トップページ `index.html` のデータ配列で `link` / `linked:true` を設定してリンク有効化
- 勢力図は `main-layout` の `height:calc(100vh - 140px); overflow:hidden` + 各カラム独立スクロールで実現
- **新規サブプロジェクト作成時は、`data/schema.json` と既存プロジェクトのコードをテンプレートとして参照すること**
